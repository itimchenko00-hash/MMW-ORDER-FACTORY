# MMW-COMPANY CONSTITUTION v1.1

Status: governance baseline, 2026-10-05.

## 1. Purpose

The Constitution protects the commercial, informational, visual, technical and operational integrity of MMW-COMPANY and its projects.

## 2. Fundamental principles

- Truth before appearance.
- Evidence before readiness.
- A concept is never presented as launched, proven or operating.
- Forecasts, scenarios and calculations are not guarantees.
- Every material economic result is traceable to explicit inputs and formulas.
- Confirmed facts, assumptions, scenarios and unknowns are visibly distinguishable.
- Roles, responsibilities and participation structures are never invented.
- Media must support the meaning of the content it accompanies.
- Project identities remain distinct while sharing company-wide integrity rules.
- Public pages use commercial language, not internal engineering or development jargon.
- A user-facing control must perform the function it communicates.
- Shared changes must not silently alter unrelated projects.
- Known recurring defects must become prevention mechanisms where technically feasible.
- Production is a controlled destination, never a testing laboratory.
- A release must be reproducible from a recorded approved version.
- Every release has a known rollback target.

## 3. Prohibited states

Release-blocking unless explicitly approved as a controlled exception:

- duplicate media where uniqueness is required;
- semantically mismatched media;
- missing or dead advertised interactions;
- duplicate primary controls with identical intent;
- hidden economic assumptions presented as facts;
- manual revenue fields where revenue should be derived;
- unsupported investment guarantees or certainty language;
- stale competing copies of project/catalog data;
- production fallback storage for business-critical records;
- internal development terms exposed publicly;
- cross-project changes without impact review;
- changes to a frozen control state;
- deployment without a rollback point;
- release without mandatory gates;
- production/source version drift;
- external media without required provenance information;
- public data collection without the required privacy/consent layer;
- recurring defects corrected manually without a prevention action.

## 4. Commercial honesty

Every project must distinguish confirmed facts, working assumptions, scenarios and unresolved questions. Location, market demand, costs, capacity, price, revenue, investment structure and return metrics remain conditional until supported by project-specific evidence.

## 5. Data lineage

Important business facts have an identifiable source. Renderers transform approved data but do not silently create competing sources. Intentional duplication requires synchronization and regression control.

## 6. Media integrity

Each asset has a stable project association and semantic purpose. External assets have source/licensing information where required. Reuse is prohibited where uniqueness is required.

## 7. Interaction integrity

Interactive elements have defined states, visible state changes, meaningful results and appropriate accessibility semantics. Runtime behavior must be tested where behavior is part of the requirement.

## 8. Economic integrity

Economic models declare inputs, units, derived outputs, dependencies and formulas. Relevant input changes must propagate to dependent outputs. Missing inputs remain visible. Results are scenarios, not promises.

## 9. Privacy and security

Personal-data forms require appropriate validation, rate limiting and privacy/consent controls before launch. Administrative functions require authorization. Secrets are never committed.

## 10. Release integrity

Production receives only an approved commit that passed applicable gates and has a rollback reference. Post-release verification compares the actual production artifact with the approved release.

## 11. Exceptions

Exceptions are explicit, scoped, justified, risk-assessed, owned and time-bounded where appropriate. An exception never silently becomes the standard.

## 12. Amendment rule

Constitutional changes require a new version, rationale, impact assessment and regression review. They never retroactively alter a frozen historical etalon.
