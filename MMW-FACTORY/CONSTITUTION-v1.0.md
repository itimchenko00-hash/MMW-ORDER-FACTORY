# MMW-COMPANY CONSTITUTION v1.0

Status: approved governance baseline, 2026-10-05.

## 1. Purpose

The Constitution protects the commercial, informational, technical and operational integrity of MMW-COMPANY and its projects.

## 2. Fundamental principles

- Truth before appearance.
- A concept is never presented as a launched or proven business.
- Forecasts, scenarios and calculations are not guarantees of future results.
- Every material economic result must be traceable to explicit inputs and formulas.
- Roles, responsibilities and participation structures must not be invented.
- A visual asset must support the meaning of the content it accompanies.
- Project identities must remain distinct while following the company-wide production standard.
- Public pages contain commercial language, not internal engineering labels or development jargon.
- A user-facing control must perform the function it communicates.
- A change must not silently alter unrelated projects or shared systems.
- Known defects must be converted into prevention mechanisms where feasible.
- A release must be reproducible from a recorded version.

## 3. Prohibited states

The following are release-blocking unless explicitly justified and approved as a controlled exception:

- duplicate media where uniqueness is required;
- semantically mismatched media;
- broken or non-functional interactive cards;
- duplicate controls performing the same primary action without a clear reason;
- hidden economic assumptions presented as facts;
- manual revenue fields where revenue should be derived from operational inputs;
- unsupported investment guarantees or certainty language;
- stale hardcoded project data when the canonical project model exists;
- production fallback storage for business-critical orders when persistent storage is required;
- internal development terms exposed on public pages;
- changes to a frozen control state;
- deployment without a known rollback point;
- a project marked ready without passing its mandatory quality gates.

## 4. Commercial honesty

Every project must clearly distinguish confirmed facts, working assumptions, scenarios and unresolved questions. Location, market demand, costs, capacity, price, revenue, investment structure and return metrics remain conditional until supported by project-specific evidence.

## 5. Data integrity

Where a canonical data structure exists, public renderers must derive from it rather than maintain a second competing source. Duplication is permitted only when explicitly intentional and covered by a synchronization rule.

## 6. Media integrity

Each project media asset must have a stable project association and a declared semantic purpose. Media registers must preserve source/licensing information where external assets are used. Reuse is prohibited where the project specification requires uniqueness.

## 7. Interaction integrity

Interactive elements require a defined state model. Buttons and cards must be keyboard-accessible where applicable, expose state through appropriate accessibility attributes, and produce the result promised by their label.

## 8. Economic integrity

Economic models must declare inputs, derived outputs and formulas. An input that claims to affect an output must actually affect that output. A result must never be presented as guaranteed. Missing inputs must be visibly identified rather than silently assumed.

## 9. Privacy and security

Forms collecting personal data require appropriate validation, rate limiting and a clear privacy/consent layer before commercial launch. Administrative functions require authentication/authorization. Secrets must not be committed to source.

## 10. Release integrity

Production is a controlled destination, not a working area. Every release must originate from a reviewed branch or commit, pass mandatory gates and retain a rollback reference.

## 11. Exception handling

Exceptions must be explicit, scoped, time-bounded where appropriate and documented with the reason, affected area, risk and owner. An exception must not silently become the new standard.

## 12. Amendment rule

Constitutional changes require a dedicated version, rationale, impact assessment and regression review. They do not retroactively alter the meaning of a frozen historical etalon.
