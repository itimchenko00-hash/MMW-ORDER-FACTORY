# MMW-COMPANY/3 — Factory Workflow

## Phase 0 — Preparation
- Confirm workspace and branch.
- Confirm Constitution, Standard, and Methodological Contour are governing documents.
- Establish clean-sheet baseline.
- No Render deployment until the build is ready for runtime QA.

## Phase 1 — Discovery and architecture
- Define company purpose, audience, offer, projects, and conversion goals.
- Define information architecture before styling.
- Define component and interaction rules.
- Define content ownership and non-duplication rules.

## Phase 2 — Content
- Write commercially honest copy.
- Separate company-level information from project-level information.
- Mark concepts/demos honestly; never imply launched status without evidence.

## Phase 3 — Visual system
- Create a coherent MMW-COMPANY visual language.
- Establish section, card, interaction, responsive, typography, spacing, and accessibility rules.
- Do not decorate before semantic structure is stable.

## Phase 4 — Implementation
- Build only against the approved architecture.
- Keep interactions functional and testable.
- Avoid duplicate components and duplicate content.

## Phase 5 — Media
WEB SOURCE → CONTROLLED IMPORT → LOCAL FACTORY ASSET → SEMANTIC PLACEMENT → PROVENANCE → QA → LIVE

- Local project assets only.
- No external runtime image dependencies.
- Every important image must have a semantic role.
- Duplicates and mismatched imagery are defects.

## Phase 6 — QA gates
- Structural QA
- Functional/interactivity QA
- Responsive/mobile QA
- Media/provenance QA
- Commercial cleanliness QA
- Constitution/standard compliance QA
- Runtime QA

A failed gate blocks progression until corrected and rechecked.

## Phase 7 — Release
- Final checkpoint on the same working branch.
- Deploy only the approved state.
- Verify the actual production result.
