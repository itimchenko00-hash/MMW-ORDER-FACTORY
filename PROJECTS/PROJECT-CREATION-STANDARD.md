# MMW-COMPANY — PROJECT CREATION STANDARD
Version: 2026-10-03
Scope: active MMW-COMPANY project ecosystem

## 1. Source and protection
- FROZEN/CONSERVE/ARCHIVE objects are read-only.
- Never move, rename, overwrite or delete a frozen file, repository, branch, deployment or asset.
- Any required source is copied into the active workspace before modification.
- One active canonical source owns each function.

## 2. Change law
- Replace canonical content; never append a second version of the same block/function.
- No duplicate DOM blocks, event handlers, media assignments, styles or parallel renderers.
- Architecture/content first; visual calibration second.
- Every project is a product of MMW-COMPANY and a concept unless independently verified as launched.

## 3. Project architecture
Every project contains the same business spine:
01 Identity / purpose
02 Product / site
03 Market / audience
04 Delivery model
05 Economics / investment
06 Team / responsibilities
07 Risk control
08 Next step
Project-specific sections may be added only when they have a distinct business function.

## 4. MMW corporate DNA
All projects inherit:
- MMW-COMPANY navigation and commercial clarity.
- Common typography hierarchy, spacing discipline, responsive rules and interaction quality.
- Clear status: Concept / Pre-development / Active only when supported by source data.
- Transparent assumptions and no implied guarantees.

## 5. Project uniqueness
Each project must define before implementation:
- unique color palette;
- unique infographic language;
- unique visual effect language;
- unique card/detail opening mechanic;
- unique semantic media map.
These differences must not break MMW-COMPANY usability or architecture.

## 6. Factory media law
- Use only approved Factory Library / project-local copied assets.
- Never generate substitute external imagery when Factory material exists.
- Copy source assets; do not mutate the source.
- Every semantic block receives one purpose-fit image or infographic where visual media adds information.
- No image is reused inside the same page when a unique approved asset exists.
- Media ownership is project-local after copying.

## 7. Commercial cleanliness
- One card = one idea / one process / one result.
- Interactive detail opens the process/result explanation without duplicating the card.
- No technical implementation language in customer-facing copy.
- Financial models use entered inputs only and visibly distinguish concept assumptions from verified data.

## 8. Future project gate
A new project cannot enter the active ecosystem until it has:
Identity → Product → Market → Model → Economics → Team → Risks → Next step → Media map → Visual identity → QA/preflight.
The same standard applies automatically to every future project.

## 9. New web-sourced media policy
- Web-sourced imagery may be used only from a source whose current license/terms permit the intended website use.
- Every downloaded/locally stored image must have a source URL, source name, license basis, retrieval date and attribution requirement recorded in the project media register.
- Do not use automated bulk scraping or systematic copying where the source terms prohibit it.
- Unsplash API imagery must follow its current API requirements, including hotlinked URLs and attribution when applicable.
- Pexels content must not be bulk/systematically copied without the permission required by its current terms.
- Prefer a curated, traceable media pack over a large unverified dump.
- Target media pack: 50 unique thematic candidates per company/project, with only legally cleared and actually acquired assets marked READY.
- Missing READY assets are never silently replaced by unrelated external imagery.

## 10. Rebuild gate
A system-wide rebuild is considered complete only when:
1. all active projects use the same canonical architecture;
2. ALADIN conforms to the same company standard;
3. each project has its own visual identity and interaction variant;
4. media is project-local or explicitly traceable to an approved source;
5. no duplicated renderer, handler, block or style layer remains;
6. preflight passes;
7. only then may the active branch be published.
