# MMW-COMPANY/2 — technical architecture

## Target state

**One company → one application → one branch → one deployment → one project registry → project records → one active media convention.**

The six developed projects are records inside the same application. Four additional portfolio slots remain potential until explicitly defined.

## Shared application layer

- `public/index.html`
- `public/app.js`
- `public/style.css`
- `server.js`

## Project layer

Project identity, copy, economics, interactions and media mapping live in the shared application registry. A project is a product/content unit, not infrastructure.

## Active media layer

Canonical future path:

`public/ASSETS/<PROJECT>/photos/web-selected/`

There must be no lowercase parallel runtime media tree, no project-specific runtime server and no external runtime image URL.

## Historical layer

Backups, snapshots and old branches are preservation/history only. They are not runtime sources.

## Media lifecycle

`WEB SOURCE → CONTROLLED IMPORT → LOCAL FACTORY ASSET → SEMANTIC PLACEMENT → PROVENANCE → QA → LIVE`

Any of the company's projects can be developed in the same active branch. No new project branch, workspace, Render service or duplicate application is required for normal work.
