# КОНСТИТУЦИЯ MMW-COMPANY · MMW-COMPANY/1

## 1. Контур
Работа выполняется только в изолированном проектном контуре MMW-COMPANY/1 и ветке MMW-COMPANY-NEW-MASTER-2026-10-01. Старые MMW-COMPANY, MMW-ORDER, Factory, законсервированные проекты, старые Render-сервисы и исторические ветки не изменяются.

## 2. Принцип замены
При изменении содержания существующая версия раздела, страницы или блока заменяется целиком. Новые слои поверх старых не накладываются. Дубликаты одной сущности запрещены.

## 3. Архитектура прежде визуала
Сначала создаются информационная архитектура, модель данных, маршруты и интерактивные сценарии, полное содержание и функциональная проверка. Только затем выполняется визуальная доводка.

## 4. Компания и проекты
MMW-COMPANY — материнская компания. ALADIN и остальные направления — самостоятельные проекты MMW-COMPANY. Единый принцип MMW может иметь разные экономические двигатели для разных типов бизнеса.

## 5. Достоверность
Концептуальные проекты обозначаются как концепты. Нельзя выдавать концепт за запущенный объект, заключённую сделку, подтверждённый бюджет, фактическую прибыль или действующую эксплуатацию.

## 6. Экономика
Финансовый контур должен учитывать релевантные для конкретного проекта расходы, доходы, инвестиции, прибыль, точку безубыточности, ROI, окупаемость, доход инвестора и доход MMW там, где эти показатели применимы. Отсутствующие фактические данные не выдумываются.

## 7. Уникальный экономический принцип MMW
Интерактивный экономический контур является фирменной частью MMW-COMPANY. Общим остаётся только методологическое ядро: исходные данные → расчёт → сценарий → результат → ограничения.

Экономическая механика не должна быть копией между проектами. Каждый проект обязан иметь собственный набор ключевых входных параметров, собственные производные показатели и собственную логику расчёта, отражающую природу бизнеса.

Текущие двигатели:
- ALADIN RESIDENCE — ALADIN DEVELOPMENT ENGINE: единицы → площадь → цена/м² → себестоимость/м² → продажи → девелоперский результат;
- NEXUS WORK — SPACE & REVENUE ENGINE: площадь → загрузка → аренда → сервисы → NOI;
- NEXUS LOGISTICS — FLOW ENGINE: склад → загрузка → хранение → обработка → операционный результат;
- CARPATHIA ECO LODGE — HOSPITALITY ENGINE: номера → загрузка → ADR → дополнительные услуги → EBITDA;
- AGROHUB — PROCESSING ENGINE: сырьё → загрузка → выход продукта → цена → переменная маржа;
- ENERGY PARK — ENERGY & ASSET ENGINE: площадь → загрузка → размещение → энергетическая маржа → результат;
- MMW-COMPANY — PORTFOLIO ENGINE: портфель → конверсия → проектная выручка → success fee → расходы → результат самой MMW.

Запрещено использовать один универсальный калькулятор с переименованными полями как замену проектной экономике.

## 8. Функциональность
Информация должна быть доступна внутри сайта через навигацию, раскрывающиеся блоки, фильтры и проектные страницы. Экономические двигатели должны реагировать на изменение каждого входного параметра без перезагрузки страницы.

## 9. Инфраструктура
Node.js обязан слушать 0.0.0.0 и process.env.PORT с безопасным значением по умолчанию 10000. Серверные таймауты настроены на устойчивую работу Render.

## 10. Этапы
Архитектура → содержание → функциональность → проверка → визуал. Каждый законченный этап фиксируется отдельным коммитом. Следующий этап не должен наслаиваться на предыдущий.

## 11. Публичный интерфейс
В публичном интерфейсе не используются внутренние названия веток, Render service ID, commit SHA, слова «конституция», «эталон», «Factory» и другие технические термины внутреннего процесса.

## 12. Экономическая достоверность
Расчёты являются моделями, а не инвестиционными гарантиями. Пустые поля дают пустой производный показатель. Если формула требует нескольких параметров, результат не показывается до их ввода. Предположения должны быть явно обозначены как предположения.

## 13. Функциональная проверка
Перед переходом к финальной визуальной доводке проверяются все публичные маршруты, проектные маршруты шести концептов, якорная навигация проектных разделов, фильтры портфеля, мобильное меню, раскрывающиеся блоки, публичные mailto-действия и повторная инициализация интерактивных экономических двигателей после смены маршрута. Проверяется также отсутствие устаревшего универсального экономического калькулятора и внутренних технических терминов в публичном интерфейсе. Проверка этого этапа фиксируется отдельно от визуальных изменений.
